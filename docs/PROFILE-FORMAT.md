# Переносимый профиль Nimbo (`.nimbo`), версия 1

Nimbo — единый формат переноса профиля между совместимыми клиентами и самостоятельно размещёнными серверами. Nimbo экспортирует `profile.nimbo`. Это файл с паролем, а не облачная учётная запись или автоматическая синхронизация.

Код проекта распространяется по [MIT](../LICENSE). Можно создавать свои интерфейсы, серверы и производные продукты. Просим сохранять совместимость с форматом Nimbo и явно указывать в интерфейсе и документации: «Поддерживается импорт и экспорт профиля Nimbo (.nimbo)». Это просьба о совместимости, а не дополнительное ограничение лицензии MIT.

## Что переносится

- Имя и аватар профиля.
- Список серверов, имя пользователя и ключ доступа отдельно для каждого адреса сервера.
- Пользовательские горячие клавиши, включая снятые назначения, одиночные клавиши и боковые кнопки мыши.
- Включение размытия камеры и его сила (`cameraEffects`), если клиент поддерживает эффект.
- Личные названия и закрепления серверов (`customName`, `pinned`), если клиент поддерживает эти необязательные поля.

Новый сервер может использовать имя, аватар и настройки из файла, но выдаёт собственный доступ. Ключ одного сервера нельзя отправлять другому. Роли, права владельца, блокировки и сообщения остаются на соответствующем сервере; файл не может назначить себе полномочия. Аппаратные идентификаторы микрофонов и камер, cookies, временные токены сессий и пароли в экспорт не входят. Остальные настройки пока не включены в v1; не обещайте перенос всех настроек устройства.

## Контейнер

Файл — UTF-8 JSON, MIME `application/octet-stream`. Каноническое расширение — `.nimbo`. Импорт также поддерживает старый незашифрованный `.json`; формат определяется содержимым.

Поля контейнера:

| Поле | Значение |
| --- | --- |
| `format` | `nimbo-encrypted-profile` |
| `version` | `1` |
| `kdf` | `PBKDF2-SHA256` |
| `iterations` | `600000` |
| `cipher` | `AES-256-GCM` |
| `salt` | 16 случайных байт, стандартный Base64 |
| `iv` | 12 случайных байт, стандартный Base64 |
| `data` | Шифротекст и следующий за ним 16-байтовый тег GCM, стандартный Base64 |

Пароль содержит от 6 до 256 символов и кодируется UTF-8 без нормализации, PBKDF2 выводит ключ 256 бит. AAD — точная UTF-8 строка `nimbo-encrypted-profile:v1:PBKDF2-SHA256:600000:AES-256-GCM`. Для каждого экспорта генерируются новые salt и IV. Пароль не записывается и не отправляется на сервер. Неверный пароль и повреждение файла дают одинаковую ошибку. Импорт не должен пытаться выполнять неограниченное число итераций из недоверенного файла: поддерживаемые параметры проверяются до расшифровки.

## Содержимое после расшифровки

```json
{
  "format": "nimbo-profile",
  "version": 1,
  "name": "Алексей",
  "avatar": "",
  "servers": [],
  "hotkeys": {
    "mic": {"code": "Home", "ctrl": false, "alt": false, "shift": false, "meta": false},
    "camera": {"code": "Mouse4", "ctrl": false, "alt": false, "shift": false, "meta": false}
  }
}
```

`servers` содержит до 64 уникальных записей `{url, name, displayName, profileKey}`. URL — origin HTTPS без логина, пароля, пути, query или fragment; локальная разработка дополнительно допускает HTTP для localhost/loopback. `profileKey` — 43 символа Base64URL `[A-Za-z0-9_-]`. Это секрет доступа, не публичный идентификатор. `name` сервера — до 60 Unicode-символов, имя пользователя — до 40, без управляющих символов. Аватар — пустая строка либо JPEG/PNG data URL до 49152 символов.

`cameraEffects` необязательно: `{enabled: boolean, strength: number}`. Сила размытия — целое число от 1 до 60, исходное значение 12. Импорт округляет и ограничивает числовое значение этим диапазоном. Поле хранится в локальном профиле и переносится при экспорте; изображение с камеры не сохраняется.

`hotkeys` необязательно: старый профиль без него сохраняет действующие назначения получателя. Если поле есть, это полная карта назначений: отсутствующее действие отключено, `{}` отключает все. Действия v1: `mic`, `camera`, `screen`, `members`, `effects`, `settings`. `code` соответствует физическому `KeyboardEvent.code`, либо `Mouse4`/`Mouse5`; четыре модификатора обязательны и имеют boolean-значения. Дублирующиеся сочетания недопустимы. Работа глобально поверх других программ не обещается: веб-клиент обрабатывает доступные браузеру события в активной вкладке вне ввода текста.

В записи сервера допускаются необязательные `pinned: true`, `customName: true`, `role: "owner" | "admin" | "member"`. `role` — лишь подсказка интерфейсу о последнем известном статусе, никогда не подтверждение полномочий. На текущем подключённом сервере отображается его фактический ответ. Добавление адреса заранее создаёт отдельный случайный 256-битный ключ для будущего первого входа; наличие такой записи само по себе не доказывает регистрацию. Смена origin создаёт новый ключ и удаляет кеш роли. Ключ старого origin никогда не отправляется на новый.

### Вход через файл и локальные профили

Начиная с web-0.4.4-10, после локальной расшифровки клиент может отправить **только ключ совпадающего origin** в `POST /api/profile-session`. Сервер проверяет ранее зарегистрированный ключ, блокировку участника, Origin и лимит попыток и выдаёт обычную сессию. Общий код не требуется для уже зарегистрированного профиля. Неизвестный ключ не создаёт участника; первый вход остаётся через код приглашения. Имя и роли из файла не изменяют серверную запись при таком входе.

Веб-клиент хранит до 16 отдельных профилей в этом браузере. Скачивание экспортирует только текущий профиль, не всю библиотеку; загрузка добавляет профиль, не стирая остальные. Повторный импорт той же идентичности не перезаписывает сохранённую запись автоматически. Удаление записи из браузера не удаляет пользователя на сервере и ранее скачанные файлы. Облачной синхронизации нет. Для другого origin файл потребуется загрузить там отдельно — данные localStorage между сайтами не передаются.

Текущий импорт ограничен 300000 байтами внешнего файла и 100000 символами внутреннего JSON. Нельзя ослаблять проверку URL, аватара, ключей и размеров при добавлении совместимости.

## Совместимость и развитие

Стабильные `format`, `version`, коды действий и криптографические параметры важнее имени продукта или собственного интерфейса. Не переименовывайте поля или AAD в производном клиенте. Дополнительные необязательные поля можно игнорировать; текущий Nimbo сохраняет только известные поля. Несовместимые изменения требуют новой версии и явной миграции. Перед заявлением о совместимости проверьте двусторонний экспорт/импорт с эталонным Nimbo, старые файлы, пустую карту хоткеев и отказ при неправильном пароле.

Эталонная реализация: `web/src/composables/profileFile.ts`, `encryptedProfile.ts`, `useHotkeys.ts`. Файл не следует загружать целиком на произвольный сервер: расшифровка и выбор нужной записи выполняются клиентом.
