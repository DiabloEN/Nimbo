# Проверка безопасности вложений — 30 октября 2026

Модель угроз: авторизованный участник пытается загрузить произвольный файл, выдать активный документ за картинку, выйти из каталога хранения, исчерпать ресурсы либо скачать файл без доступа. Ориентир проверки — [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html). Это проверка конкретного механизма, а не заключение о полной безопасности сервиса.

## Реализованные ограничения

- **Выполнение кода и перезапись приложения.** Имя пользователя не используется как путь хранения. Файл получает случайный 256-битный идентификатор без расширения, записывается с правами 0600 в каталог 0700 вне веб-каталога. В контейнере API нет оболочки и интерпретаторов; он работает от UID 65532 с файловой системой приложения только для чтения и без capabilities. Приложение не запускает вложения и не извлекает архивы на диск.
- **Обход путей и обман именем.** Убираются компоненты пути; запрещены управляющие символы, двоеточие (в том числе NTFS ADS) и невидимые Unicode-символы форматирования. Отображение имени происходит через текстовые узлы Vue, без HTML-интерпретации.
- **XSS и подмена типа.** API отдаёт файл как `application/octet-stream`, `Content-Disposition: attachment`, с `nosniff` и CSP sandbox. Предпросмотр использует только img/audio/video через локальные Blob URL. HTML, SVG, PDF и офисные документы не встраиваются. Проверяются расширение и сигнатура поддерживаемого медиа, для PNG/JPEG/GIF/WebP — также предел 8192 пикселя по стороне и 24 млн пикселей. Это ограничение декодирования, не доказательство безвредности медиа.
- **Доступ.** Загрузка и скачивание требуют действующей сессии участника; учитываются блокировка, ограничения чата и разрешение загрузки в канале. Идентификатор файла сам по себе не даёт анонимный доступ. В нынешней модели участникам доступны текстовые каналы своего сервера; будущие приватные каналы потребуют отдельной проверки ACL.
- **Квоты и временные файлы.** Лимит 20 MiB, ограничение размера multipart-тела и времени чтения, не более двух одновременных загрузок. Проверяется свободное место и общая квота до фиксации сообщения. Отказ не должен удалять историю. Временный файл не публикуется; после ошибки удаляется. После аварийного завершения процесса возможны осиротевшие файлы — автоматическая сверка каталога при старте пока не реализована.
- **Антивирус.** Публикация разрешена только после точного ответа `stream: OK`. Ошибка, отсутствие сканера, тайм-аут и обнаружение угрозы не публикуют файл. Если владелец включил проверку во время загрузки, непроверенный файл не публикуется. Общая настройка сервера имеет приоритет над старой настройкой отдельного канала.
- **Архивы.** Выявлено: ClamAV может вернуть OK, пропустив слишком большой элемент ZIP. Поэтому Nimbo дополнительно читает только каталог ZIP: максимум 1000 элементов, не более 20 MiB суммарно после распаковки, без зашифрованных элементов и вложенных архивов известных типов. Содержимое не извлекается. У ClamAV дополнительно ограничены глубина, число файлов, время и общий объём сканирования. Для прочих форматов архивов действуют ограничения самого ClamAV; поддержка формата и полнота проверки не гарантированы.
- **Изоляция сканера.** ClamAV и обновлятор работают от пользователя clamav, не root. Только закрытые Unix-сокеты, без порта в Интернет. Служба ограничена 2 GiB RAM и 60% одного CPU (30% суммарной мощности этого двухъядерного VPS), не имеет прав менять приложение и приватные настройки. AppArmor остаётся включён; добавлено чтение только собственных конфигураций и доступ к собственному сокету.
- **Обновления.** Веб-интерфейс владельца может запросить лишь фиксированную операцию freshclam. Имена файлов, shell-команды и адреса загрузки от клиента не принимаются. Обновления сериализованы и ограничены по частоте. Кнопка обновляет сигнатуры; установку новой версии движка выполняет администратор ОС. Во время обновления баз сканер останавливается, чтобы не держать два движка в RAM; файлы остаются в черновиках при отказе проверки.

## Проверки и границы

Автотесты покрывают доступ к управлению антивирусом только владельцу, приоритет общей политики, отказ при недоступном сканере, приватные имена и права, безопасные заголовки скачивания, обход путей и обман имени, границы размера, отклонение большого/вложенного ZIP, поддельные медиа и чрезмерные размеры изображения. Для Linux предусмотрен отдельный `TestRealScannerFileUpload` с настоящим ClamAV и временной тестовой базой: без публикации в рабочем чате.

Антивирус не заменяет остальные ограничения и не защищает от всех новых угроз. Скачанный файл может быть опасен при ручном запуске на компьютере получателя. Остаются риски уязвимостей нативных декодеров браузера, парсеров ClamAV и злоупотребления легальными загрузками/скачиваниями. Перед публичным релизом нужны независимый аудит, нагрузочные тесты, тесты восстановления после аварии, актуальные версии ОС/ClamAV/браузеров и отдельный анализ всей аутентификации. Файлы сейчас не имеют сквозного шифрования; оператор сервера технически имеет доступ к их содержимому.
