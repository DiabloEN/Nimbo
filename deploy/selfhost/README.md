# Самостоятельная установка Nimbo

Предварительный установщик Linux amd64: API Nimbo, LiveKit, Caddy и опциональный ClamAV. Без Grafana, общей авторизации и доступа разработчика к вашей установке. Репозиторий пока приватный, подписанного публичного выпуска и загрузки одной командой ещё нет.

## Подготовка

Нужны Linux с systemd (ориентир Ubuntu/Debian), Docker Engine с Compose v2, Python 3, OpenSSL, util-linux (`fallocate`), e2fsprogs (`mkfs.ext4`), Certbot для автоматических сертификатов. На Debian/Ubuntu недостающие утилиты устанавливаются через `sudo apt-get install certbot e2fsprogs util-linux`. Сам установщик не обновляет ОС, Docker и не меняет SSH.

Нужен публичный IPv4 на интерфейсе VPS и три DNS-имени: приложение, сигналинг звонков и TURN. A-записи направьте на этот VPS. AAAA добавляйте только при рабочем IPv6. CDN-проксирование медиасервера не поддерживается. Установка по голому IP и за NAT пока не реализована.

Для сборки из исходников с Go, Node и установленными зависимостями `web/node_modules`: `node scripts/package-selfhost.mjs`. Архив создаётся в `artifacts/selfhost/`. Он содержит сервер, установщик, CLI, host.py, Dockerfile, SHA256SUMS и antivirus/. Контрольная сумма проверяет целостность, а не подлинность издателя; подпись релизов — отдельный этап. Автоматические тесты запускаются отдельно.

## Порт выбираете вы

Из распакованного проверенного пакета:

```sh
sudo python3 install.py --domain chat.example.org --rtc-domain rtc.example.org --turn-domain turn.example.org --public-ip 203.0.113.10
```

В терминале появится вопрос «Порт подключения Nimbo». Первым предлагается 8443, если он свободен. Иначе установщик предложит другой свободный порт. Enter подтверждает предложение. Можно выбрать 443 либо свободный порт 1024–65535. Без терминала обязателен явный `--https-port`; незаметного выбора порта нет.

Пример полностью определённых параметров для VPS с 6 GiB RAM и 2 vCPU:

```sh
sudo python3 install.py --domain chat.example.org --rtc-domain rtc.example.org --turn-domain turn.example.org --public-ip 203.0.113.10 --https-port 8443 --antivirus on --memory-mib 1536 --cpus 2 --storage-gib 10
```

Адрес подключения будет `https://chat.example.org:8443`. Порт 443 записывается без суффикса. Приглашения используют этот адрес. По умолчанию имя Compose — `nimbo-8443`, каталог — `/opt/nimbo-8443`; можно явно задать `--project` и `--directory` (новый абсолютный путь без пробелов).

Служебные порты подбираются автоматически в диапазоне 20000–39999, отдельно для TCP/UDP. Можно указать каждый вручную: `--api-port`, `--signal-port`, `--rtc-tcp-port`, `--rtc-udp-port`, `--turn-tls-port`, `--turn-udp-port`. API и сигналинг слушают loopback, их не нужно открывать наружу.

Реестр `/var/lib/nimbo-installer/instances.json` хранит только каталоги, порты и бюджеты ресурсов. Блокировка исключает одновременную выдачу одинаковых портов новым установкам. Остановленные и подготовленные через `--prepare-only` установки сохраняют резервирование. Проверяются также фактически занятые IPv4/IPv6-порты. Старые установки и сторонние приложения, не внесённые в реестр, не получают автоматического резервирования после остановки. Не удаляйте записи реестра, пока установка может быть запущена.

## Сертификаты и firewall

На выбранном порту работает HTTPS. Сертификаты автоматически получает Certbot: отдельный ACME-каталог и ключи каждой установки. В обычном режиме на время выпуска/продления нужен свободный входящий TCP 80. Nimbo постоянно его не занимает; выдачи сертификатов между установками сериализуются.

Если порт 80 уже занят вашим сайтом, используйте `--acme-webroot /путь/к/webroot`. Существующий HTTP-сервер должен отдавать `/.well-known/acme-challenge/` из этого каталога для всех трёх DNS-имён. Установщик не переписывает конфигурацию чужого сайта. Поэтому страница проекта может оставаться на обычном HTTPS 443, а Nimbo — на 8443.

После успешного запуска создаётся отдельный systemd timer: два раза в сутки проверяет необходимость продления. При замене сертификата перезапускаются только работающие Caddy и LiveKit данной установки; звонки при таком перезапуске могут кратковременно прерваться. Остановленные установки не запускаются. Ручная проверка: `nimbo renew-certificates`. Ошибки смотрите через `systemctl status nimbo-ИМЯ-ПРОЕКТА-certificates.service`.

Альтернатива: `--certificate-directory /root/certificates`, где лежат `app.crt/app.key`, `rtc.crt/rtc.key`, `turn.crt/turn.key`. Проверяются домены, срок и соответствие ключам. Эти сертификаты копируются и **не обновляются автоматически**.

По умолчанию firewall остаётся под управлением администратора, а установщик печатает точный список. `--firewall ufw` добавляет только необходимые правила в **уже активный** UFW: выбранный HTTPS, TCP медиасервера/TURN, UDP медиасервера/TURN, TCP 80 для ACME. Не включает UFW, не сбрасывает правила и не трогает SSH. Внешний firewall панели хостинга нужно настроить отдельно. Docker host network не обходит firewall публикацией bridge-портов.

`nimbo check` проверяет HTTPS с валидацией сертификата и ответ API с самого VPS. Это не доказательство доступности снаружи. Выполните с другого компьютера напечатанную команду `curl --fail --max-time 10 https://chat.example.org:8443/healthz`. UDP, TURN и звонки проверяйте между двумя разными сетями. Успешный TCP healthcheck не подтверждает работу UDP.

## Несколько серверов и ресурсы

Каждой установке выделяются отдельные контейнеры, каталог, база, ключи и дисковый том. Новый порт автоматически даёт другое имя и каталог. Для независимых операторов рекомендуются разные домены: браузерные cookie не изолируются портами; отдельный namespace предотвращает только случайное перезаписывание cookie. Это не отдельные VM: сеть host, ядро, диск и root VPS общие.

- `--memory-mib 1536`: суммарный жёсткий лимит API, LiveKit и Caddy, по умолчанию 256/1024/256 MiB. Swap для контейнеров отключён. При достижении лимита процесс может быть остановлен OOM, а не получить память соседа.
- ClamAV добавляет ещё 3072 MiB. Сумма бюджетов зарегистрированных установок плюс 512 MiB для ОС должна помещаться в RAM. При нехватке установка останавливается до создания тома. Для стандартных лимитов с ClamAV нужен VPS минимум около 5 GiB; практический ориентир **6–8 GiB, от 2 vCPU**. На 4 GiB понадобится уменьшить лимиты основных сервисов или выбрать установку без отдельного ClamAV. Это не гарантия количества звонков.
- `--cpus 2`: суммарный потолок CPU для всех контейнеров установки, включая антивирус. Доли разделены между сервисами. Сумма бюджетов реестра не может превышать число логических CPU. Это потолки, а не эксклюзивное закрепление ядер; возможна конкуренция с процессами вне Nimbo.
- `--storage-gib 10`: **заранее выделенный**, не sparse, файл ext4 фиксированного размера. Внутри — сообщения, вложения и базы ClamAV. Нельзя заполнением вложений выйти за размер тома. Монтаж через отдельный systemd mount unit с `nodev,nosuid,noexec`. При отсутствии смонтированного тома CLI откажется запускать сервер; Docker bind mounts не создают пустой каталог вместо данных.
- Образы Docker, небольшие конфиги/сертификаты, журналы и ваши резервные копии находятся вне тома. Docker-журналы ограничены 3×10 МБ на контейнер. Для установки требуется ещё 3 GiB свободного диска сверх тома. I/O, пропускная способность сети и сторонние программы не получают полной изоляции этими лимитами.

На заполненном томе новые записи могут отклоняться; увеличение файловой системы и очистка старых установок пока выполняются администратором. Не форматируйте существующий `storage.ext4`. Автоматического удаления данных, контейнеров соседей и Docker prune нет.

## Антивирус

ClamAV предлагается по умолчанию при RAM от 4 GiB. Ниже порога/при неизвестной памяти нужен явный ответ да/нет либо `--antivirus on|off`. Затем отдельно проверяется, помещается ли выбранная конфигурация по лимитам. На VPS «4 ГБ» ОС часто сообщает меньше 4 GiB.

Сканер работает от непривилегированного пользователя, без доступа к базе чата/секретам приложения и без сетевых портов. Базы загружаются с инфраструктуры ClamAV; файлы пользователей туда не отправляются. Базы обновляются автоматически, текущая версия и ручная проверка обновления доступны владельцу в настройках. Официальная [рекомендация ClamAV](https://docs.clamav.net/manual/Installing/Docker.html) — 3–4 GiB для движка; установлен потолок 3 GiB. Старая копия движка останавливается перед обновлением, проверки на это время недоступны.

Установка ждёт готовности до 10 минут. Сбой сканера **не отключает проверку**, непроверенные вложения блокируются. `--antivirus off` не разрешает автоматически загрузку без проверки: это отдельный выбор владельца в приложении. Отключение проверки в интерфейсе не останавливает контейнер сканера. Версию движка обновляют пересборкой образа; обновление сигнатур не обновляет сам движок.

## Управление и первый вход

```sh
sudo nimbo help
sudo nimbo status
sudo nimbo check
sudo nimbo owner-code
```

Если на VPS несколько установок, `sudo nimbo help` покажет их имена. Выберите нужную, например `sudo nimbo --instance nimbo-8443 status`.

Короткую команду добавляет установщик. Для ранее зарегистрированных установок выполните один раз `sudo python3 -I nimbo_cli.py --install` из распакованного нового пакета. Если `/usr/local/bin/nimbo` уже занят другой программой, используйте `sudo ./nimbo status` из каталога установки.

Чистый сервер не имеет владельца и закрыт для обычной регистрации. `owner-code` выдаёт одноразовый код на 30 минут; добавьте адрес в совместимом клиенте и используйте код как приглашение. Установщик не создаёт за вас профиль. Повторная выдача отменяет предыдущий код; после назначения владельца выдача отказывает. API хранит хеш кода. CLI кратковременно останавливает только API этой установки, так как JSON-база рассчитана на одного писателя.

По умолчанию отдаётся только API и healthcheck; `--web-preview` включает встроенный веб-клиент для приёмки. `--prepare-only` создаёт конфигурацию и резервирует порты/ресурсы, но не создаёт тома, сертификаты, правила firewall или контейнеры. Затем `nimbo install` создаст том, получит сертификаты и запустит сервер; firewall в этом сценарии настраивается вручную по распечатанному списку.

`nimbo stop` сохраняет данные. Перед копированием базы остановите API; храните также приватную конфигурацию. Профиль `.nimbo` пользователь сохраняет отдельно. Эта версия пока **не реализует E2EE сообщений**: HTTPS защищает транспорт, база содержит текст. В «Настройки → Общие → Обновления сервера» владелец видит версию установленного приложения. Служба хоста проверяет GitHub при запуске и каждые шесть часов. Для публикации соберите пакет с NIMBO_SERVER_VERSION, равной тегу server-vX.Y.Z, и приложите nimbo-server-linux-amd64.tar.gz к стабильному неизменяемому релизу DiabloEN/Nimbo. Установщик сверяет SHA-256 с метаданными GitHub и версию внутри исполняемого файла. Обновляется серверное приложение с веб-клиентом. Дождитесь окончания звонков. Резервная копия сохраняется в private/before-update-*; при неудачном старте служба восстанавливает программу и данные. Службу устанавливает новый установщик. Для прежних установок требуется однократное подключение службы на хосте.
