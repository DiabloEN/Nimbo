# Вложения в чатах

До 10 вложений в одном сообщении, суммарно до 20 MiB (20 × 1024 × 1024 байт). Владелец управляет разрешением загрузки для каждого текстового канала, а антивирусной проверкой — в общих настройках. Отдельной роли владельца канала сейчас нет.

По умолчанию загрузка выключена. Установщик selfhost по умолчанию подключает локальный ClamAV (при ОЗУ менее 4 GiB нужен явный выбор); при ручном развёртывании администратор настраивает сканер отдельно; без проверки владелец может включить загрузку явно. Скрепка слева доступна всегда; при выключенной загрузке выводится объяснение. Выбор файла и drag-and-drop добавляют его в черновик, а не отправляют. Включение проверки антивирусом вынесено в Общие и применяется ко всем каналам. Изображения и поддерживаемое аудио/видео имеют безопасный предпросмотр; остальные файлы доступны только для скачивания.

## Локальный антивирус

Подключение задаётся для процесса API переменной окружения:

```text
NIMBO_CLAMD_ADDRESS=127.0.0.1:3310
```

или Unix-сокетом:

```text
NIMBO_CLAMD_ADDRESS=unix:/run/clamav/clamd.ctl
```

Допустим только loopback TCP или локальный Unix-сокет. `127.0.0.1` относится к сетевому пространству процесса API: в контейнере это сам контейнер, а не автоматически хост. Для отдельного контейнера ClamAV используйте общий Unix-сокет с подходящими правами или осознанно общее сетевое пространство. Не публикуйте порт 3310 в Интернет. Установщик selfhost настраивает ClamAV и обновление баз автоматически; при ручной установке их настраивает администратор; наличие переменной ещё не означает, что сервис исправен. [ClamAV о clamd, freshclam и сокетах](https://docs.clamav.net/manual/Usage/Scanning.html).

Сканер должен принимать поток размером 20 MiB. Настройки ограничений архивов, зашифрованных документов и актуальность сигнатур тоже принадлежат администратору. Nimbo посылает содержимое через INSTREAM и принимает только точный положительный ответ. Ошибка, тайм-аут, превышение лимитов сканера или обнаружение угрозы не публикуют файл. Результат «проверено» не гарантирует отсутствие неизвестных угроз. Внешние облачные антивирусы не используются.

## Хранение и ограничения

Файлы находятся в каталоге `files` рядом с `NIMBO_DATA_FILE`, под случайными идентификаторами. Оригинальные имена служат только для скачивания. Резервировать и восстанавливать нужно согласованно JSON-базу и этот каталог.

Загрузка и скачивание требуют действующей сессии участника. Загрузка учитывает блокировку чата, настройку канала и квоту хранилища. Одновременно принимаются две загрузки; внутри каждой файлы проверяются последовательно. Сообщение с несколькими вложениями публикуется только после проверки всех файлов; отказ любого отменяет весь набор; повтор с тем же идентификатором сообщения не создаёт второе сообщение. Переполнение при загрузке не удаляет историю ради нового файла. Удаление сообщения удаляет все его файлы; общая автоматическая очистка истории также освобождает вложения.

При аварийном завершении процесса между сохранением файла и фиксацией JSON возможны неиспользуемые файлы. Автоматическая очистка таких остатков при запуске пока не реализована; не удаляйте файлы по возрасту, проверяйте отсутствие их идентификаторов в резервной и текущей базе при остановленном API.

Если перед API стоит reverse proxy, его лимит тела запроса должен вмещать 20 MiB плюс multipart-поля. API ограничивает тело размером 20 MiB + 64 KiB, приём — 120 секундами, обработку/ответ — 160 секундами. Прокси должен допускать соответствующее время. На dev установлен ClamAV 1.5.4. Проверен реальный API с настоящим сканером в изолированной тестовой базе, включая 20 MiB, EICAR и слишком большой ZIP. Проверка через внешний прокси полноценной отправки файла в рабочий чат не выполнялась.


Подробности защиты и оставшиеся ограничения: [FILE-UPLOAD-SECURITY.md](FILE-UPLOAD-SECURITY.md). Управление базами подключается через NIMBO_ANTIVIRUS_MANAGER_SOCKET (закрытый Unix-сокет). Пример службы — deploy/antivirus; install-dev.sh предназначен только для текущего тестового VPS. Отключение проверки в интерфейсе не останавливает службу ClamAV. Во время обновления сигнатур публикация вложений временно недоступна, черновик сохраняется.

Черновики представлены компактными плашками 76px: миниатюра 60px, имя и размер справа. Выбор и перетаскивание добавляют к набору; файлы убираются отдельно. Картинка открывается по клику, видео — кнопкой увеличения на кадре. У картинки Скачать — поверх кадра при наведении/фокусе, на сенсорном устройстве кнопка видна постоянно. У видео и аудио скачивание находится в нативном меню плеера, дополнительных кнопок нет. Escape/крестик/нажатие вне окна закрывают просмотр. Обычные файлы и неподдерживаемые медиа сохраняют строку скачивания.


## Быстрое отображение медиа (web-0.4.4-32)

Сохранённые изображения и плееры используют `/api/session/media/{id}`. Это закрытый маршрут под уже существующей HttpOnly-cookie `/api/session`: каждое обращение, включая Range/HEAD, проверяет срок сессии, блокировку/участие и наличие вложения в доступном канале. Ключей в URL нет. SameSite Strict, проверка Origin и Sec-Fetch-Site, CORP same-origin, nosniff, sandbox и private/no-store сохранены. [Go ServeContent](https://pkg.go.dev/net/http#ServeContent) обслуживает диапазоны байтов: не нужно сначала ждать полный Blob видео/аудио. Фактический объём предварительной подгрузки выбирает браузер и формат файла.

До inline-выдачи сервер проверяет расширение вместе с сигнатурой, для PNG/JPEG/GIF/WebP — также размеры (8192 по стороне, 24 млн пикселей). Читаются только первые 64 KiB для проверки метаданных, содержимое не исполняется. HTML/SVG/PDF/AVIF/неизвестное и несовпадающие сигнатуры не отдаются inline; остаётся безопасное отдельное скачивание. Это проверка типа/размера, не доказательство отсутствия уязвимости декодера.

Несколько фото/видео в одном сообщении показываются миниатюрами 160×120 с переносом. У видео кнопка play поверх кадра. Аудио и остальные файлы отдельными строками ниже галереи. Лимит прежний: до 10 вложений, всего до 20 MiB. Одиночное фото/видео имеет крупный кадр. Пока данные идут, место зарезервировано; промежуточной строки «Загружаем предпросмотр» и карточки скачивания нет. Картинка всё равно требует получения своих данных по сети; мгновенное получение всего файла не обещается.

Свой аудиоплеер: круглая play/pause, имя, время, перемотка по доступному range, кнопка скачать внутри. Полоски показывают живые частотные уровни AnalyserNode, а цвет — временной прогресс. Это не заранее рассчитанная форма волны всей записи. [MediaElementAudioSourceNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/createMediaElementSource) анализирует лишь проигрываемый файл локально, без микрофона/отправки аудио куда-либо. Нет полного decodeAudioData; RAF ограничен ~22 кадрами/с, отключается на паузе, скрытой вкладке (считывание частот) и при reduced-motion. При старте другого трека предыдущий ставится на паузу. Контекст закрывается при удалении компонента.
